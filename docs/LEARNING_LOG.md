# Learning Log

Concepts learned while building, including infrastructure problems. Each entry: what happened, the concept, what to study next.

---

## 2026-10-02 · Reading LearnHouse before running it

Source review of `learnhouse/learnhouse@dev` (`5e28b07`), done from a cloud session before the first run on DavidLab.

### Config precedence: env vars beat YAML
`config.py` reads every setting as `os.environ.get("LEARNHOUSE_…") or yaml_value`. `config.yaml` holds safe defaults, `.env` overrides them. This is the [12-factor](https://12factor.net/config) "config in the environment" idea.
**Study next:** `python-dotenv`, and why secrets never belong in YAML committed to git.

### Two ways to create a schema: `create_all` vs Alembic
On startup the API calls `SQLModel.metadata.create_all`, which creates any missing table from the Python models. Alembic migrations are only applied on upgrades. Consequence: a new model shows up in dev **even without a migration**, so a forgotten migration stays invisible until production. Fix: `alembic stamp head` once, then always autogenerate and run migrations.
**Study next:** Alembic `stamp`, `revision --autogenerate`, and reviewing autogenerated migrations.

### Embeddings and vector dimensions
pgvector stores fixed-length vectors: `Vector(768)`. The embedding model must output exactly 768 numbers, and every stored vector must come from the same model to be comparable. Changing model or size means a migration plus re-embedding all content.
**Study next:** cosine similarity, chunking strategies, `nomic-embed-text` vs `gemini-embedding-001`.

### Provider fallback in the AI layer
Anthropic has no embeddings API, so LearnHouse falls back to Google when a Gemini key is set. The code picks a provider in one function (`build_embedding_model`) and the rest of the app doesn't care. That's the **strategy pattern** behind "never hard-code a provider".
**Study next:** Pydantic AI `Embedder` and model abstractions.

### Backend-for-frontend proxy
The browser never calls FastAPI directly. Next.js forwards `/api/v1/*` to the API (`app/api/v1/[...path]/route.ts`). Cookies stay same-origin, and CORS headaches mostly disappear.
**Study next:** Next.js route handlers, hop-by-hop headers.

### Shared JWT secret between services
The collab server verifies the same HS256 JWT as the API, so both env files carry the same `LEARNHOUSE_AUTH_JWT_SECRET_KEY`. Decoding pins the algorithm list to block algorithm-confusion attacks.
**Study next:** JWT structure, HS256 vs RS256, why `alg: none` attacks existed. (Ties into the IAM track: OAuth/OIDC tokens are JWTs too.)

### Feature flags as data
Org features (communities, podcasts, signup mode, menu) live in a JSON column on `OrganizationConfig`. Turning a feature off is a settings change, not a deploy, and needs no migration.
**Study next:** JSONB in Postgres, trade-offs of config-in-database vs config-in-code.

### Cloud sandbox limits (infrastructure)
The cloud session could clone GitHub but couldn't pull Docker Hub images, install `postgresql-16-pgvector` from apt, or download Python 3.14.7 through `uv`. A network allowlist blocks them. Phase 0 runs on DavidLab for that reason.
**Study next:** egress allowlists and proxies, a common security control in corporate networks.

### CRLF vs LF line endings (infrastructure)
Git for Windows checked `setup-tools.sh` out with CRLF endings (`core.autocrlf=true`). Bash then read `\r` as part of each line and failed with `$'\r': command not found` and `set: pipefail: invalid option name`. Fix: `.gitattributes` with `*.sh text eol=lf` forces LF on every checkout, whatever the machine's git config.
**Study next:** `.gitattributes` and `core.autocrlf`, how to spot hidden carriage returns (`file script.sh`, `cat -A`).

### Regex greediness when parsing text (Python)
The first inbox parser used `https?://\S+` for URLs, which also swallowed the `:` in `https://x.com/a: description`, so the URL and title came out wrong. A unit test on the real `notes/inbox.md` lines caught it. Fix: end the match on a character that is not punctuation, `[^\s.,;:)]`.
**Study next:** greedy vs lazy quantifiers, `re` named groups, and why tests built from real data find bugs that invented examples miss.

### Lint your own data
`scripts/notes/check_notes.py` treats markdown frontmatter like a schema: required fields, allowed enum values, and foreign keys (topics referenced by other files must exist). Same idea as database constraints, applied to files, and it finds problems before an importer does.
**Study next:** JSON Schema, Pydantic validation, referential integrity in PostgreSQL.
